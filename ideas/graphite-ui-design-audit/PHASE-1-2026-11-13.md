## Candidate A.1 — bookmark tooltip label preservation (not deployed)

- The custom `SidebarDelegate` uses `QFontMetrics` elision with the Qt `ElideRight` setting to shorten long labels.
- During `FinderSidebar` model rebuilding, ordinary locations set their tooltip to a filesystem path or display URL via `item->setToolTip(...)`. Thus a renamed bookmark's full **display label** is not guaranteed to appear in the tooltip, even though the path remains available.
- Cloud activity status tooltips are separately refreshed in `updateCloud()`; do not overwrite them.
- The alpha values and visible selection shapes have not been shown to cause an accessibility defect; do not alter the paint colors without operator observation.

## A.4 / A.5 source trace — remote-only navigator styling and bypassed editor bridge

Operator-provided **read-only source / process output** clarified the two requested UI inconsistencies:

- `source/src/dolphinnavigatorswidgetaction.cpp` creates `DolphinUrlNavigator`, and its `finderNetworkComboV21` / `finderNetworkAddressV21` object names plus local styles are applied while navigating to the `remote` scheme. Their earlier object names and styles are restored when leaving that scheme. **Therefore a normal local-path address bar is not consistently covered by those remote-only rules.** The remote frame is independently maintained in the existing v2.2.2 work; do not overwrite those guards or change network/protocol functionality in A.4.
- The independent MIME/file-type editor bridge under the user's private Finder v1.9 lab is present. It invokes `/usr/bin/keditfiletype` with `-stylesheet` **only if** its configured QSS exists, but its hard-coded QSS points to the historic v15 stylesheet, not the current A.3 graphite candidate.
- An observed running process had the command line `/usr/bin/keditfiletype --parent [window-id] application/x-desktop`, **without** `-stylesheet`. Thus no stylesheet was passed to that instance **via the v1.9 wrapper**. It could have been launched directly, or by another path; the process command line alone does not prove exactly which code spawned it. Under the current direct A.1 binary invocation, the historic launcher path/PATH bridge was not deliberately enabled.
- Current QSS contains extensive `KPropertiesDialog` selectors, applying to the in-process Finder properties dialog, whereas `keditfiletype` is an external process with its own class tree and stylesheet scope. Avoid conflating those windows.

**Next gate before changes:** inspect the exact local-path `DolphinUrlNavigator` widget class/object names plus relevant QSS selectors, and inspect code responsible for launching MIME editor (PATH vs absolute service invocation). ## Source-backed A.4 / A.5 candidate design — 2026-11-13

After the operator supplied the exact `dolphinnavigatorswidgetaction.cpp` snippets, the experimental scope was refined with upstream KDE source confirmation:

- The local Finder builds a `DolphinUrlNavigator`, which inherits KDE's `KUrlNavigator`, and its edit widget is `KUrlComboBox` with a nested `QLineEdit`. The existing v2.2.2 remote-scheme code saves/replaces widget style/object-name/size state and restores it on return to ordinary local URLs. Targeting local-path appearance via **DolphinUrlNavigator descendant selectors** avoids editing those existing remote state guards. Runtime testing of `remote:/` remains mandatory because selector match/cascade is not settled from code alone. Upstream evidence: [Dolphin URL navigator source](https://github.com/KDE/dolphin/blob/master/src/dolphinurlnavigator.cpp).
- In KDE Frameworks WidgetsAddons, `KMimeTypeEditor` resolves `keditfiletype` through `QStandardPaths` and uses a detached process with `--parent` and the MIME argument. The separate editor in kde-cli-tools constructs a `FileTypeDialog` (a `QDialog`) containing `FileTypeDetails`, tabs and standard widget controls. An **operator-local PATH-prepended wrapper** can be tested without installing any user/global executable and can pass a standalone QSS only to this external process. Upstream evidence: [KDE MIME launcher](https://github.com/KDE/kwidgetsaddons/blob/master/src/kmimetypeeditor.cpp) and [kde-cli-tools file type editor](https://github.com/KDE/kde-cli-tools/blob/master/keditfiletype/keditfiletype.cpp).

A new **independent offline A.4/A.5 LAB package** was authored, with a fail-closed generator and two named QSS overlays:

1. **A.4 address:** appends only `DolphinUrlNavigator KUrlComboBox` and nested-line-edit rules (neutral graphite background, padding, focus/hover borders, compact drop-down) to the user-tested A.3 QSS. It pins A.3 SHA-256 `68c1a383a17c47dfe84d61350fc39590c708c8efb42616f4ac229bce876dc6e9` and produces a separate `graphite-A4-address.qss`; it does not change C++ source or rebuild Finder.
2. **A.5 external MIME editor:** a separate `graphite-A5-keditfiletype.qss` with `FileTypeDialog`-scoped selectors, plus a private `bin/keditfiletype` wrapper that invokes the official `/usr/bin/keditfiletype` with `-stylesheet`. This wrapper is never placed into the user's permanent PATH, is not used outside the isolated Finder test, and must be verified via the process command line. The operator should never click Apply/OK to modify a real MIME association during a visual trial.
